# Grill agenda — branches to resolve before the PRD

Use with: `/grill-me the brief is @client-brief.md, prior knowledge is @research.md, style specs are in styles/, reference pack is @docs/reference/README.md, and every branch in @docs/grill-agenda.md must be resolved before you stop.`

1. Style system: how a prompt word maps to a style spec; unknown style → default; what a spec must contain; how user references refine a spec.
2. Job inputs: every job takes (a) the raw video, (b) a written brief for the short (topic, angle, must-say facts, hook wish; free text, not one line), (c) a style choice from styles/, (d) optional reference images the user uploads; how each is captured in the app, validated and stored; user-supplied images outrank sourced ones and are logged as owner-supplied; how the brief and references reach the planner.
3. Beat grammar: what a "beat" is; min/max beat length; presenter modes (full / PIP / off) and the rules for switching; PIP framing rule; PIP framing priority when head plus collar exceeds the source square (keep chin vs keep hair) versus a recording guideline for the presenter; how the hook beat is built.
4. B-roll: visual kinds per beat (image, clip, card, map, chart, stamp, lower-third); motion per kind; entity beats (a named person, place, product) vs abstract beats (an idea, a feeling) and which kinds each may use; B-roll count per 60 s (references: 20–28 assets); fallback when nothing relevant is found.
5. Asset sourcing: per beat, search or generate or skip, and who decides; order of sources; relevance check on a found asset (who judges, against what, when it rejects); aspect-ratio handling for landscape and square sources in a 9:16 frame; rights-log format (per-asset fields, where it lives, how it reaches the credits and the AI disclosure); ASSET_POLICY switch; image generation (which API, prompt style, cost cap); API budget per short across search, generation and planner calls; caching per job.
6. Captions: word-sync source; phrase length; typography; keyword emphasis rule; safe area vs PIP and B-roll; the inter-word gap spec so the active-word scale does not collide with neighbours (research.md section 12).
7. Sound: music library and selection by mood; ducking numbers; allowed hit types and hit placement (research.md open item 3); the no-sweep rule as a hard, testable check; loudness targets.
8. Planner: one LLM call or two (beats vs assets); JSON schema; validation and clamping; retry; cost per call; `claude_code` vs `api` adapters.
9. Render engine: DECIDED hybrid (research.md §12: Remotion visual layer; ffmpeg for cut, stems, mix, mux; plan JSON engine-agnostic) — confirm, then: deployment weight; v1 style scope tied to the engine choice (which of the four styles ship in v1 and which need the Remotion layer); transitions vocabulary per style (which enter/exit transitions each spec may name and the renderer must implement).
10. QA gates: technical checks list (each one command); editorial rating capture and the pass line (rubric ≥ 7?); a vision-critic gate that compares output frames against docs/reference; contact sheet; how the system proves it hit the bar; what "done" means for a job.
11. Jobs and product: statuses, progress, errors, passcode, limits, retention sweeper, cost accounting per job; the ₹50 cap on a shared deployment with `PLANNER=api` (what it counts, whose subscription, what happens when a job would exceed it).
12. Testing: fixture clip; fakes for transcriber, style director, assets, image gen; which modules get boundary tests.
13. n8n-bridge replacement: which of the five old bridges (ASR, web scrape, asset download, AI image, Drive relay) become direct calls in this repo, which are dropped, and what needs internet at runtime.
14. Out-of-scope confirmation and the worth-continuing line.
